# Інфраструктура: як вийти в інтернет і зайти з телефона

## Що з чого складається

```
 📱 телефон (браузер)
      │  http(s)://<IP або домен>:<порт>
      ▼
 🌐 інтернет
      │
      ▼
 📶 роутер ── проброс порту (port forwarding) 3000 → ваш ПК
      │
      ▼
 🛡  брандмауер Windows ── дозволити вхідний TCP 3000
      │
      ▼
 🟩 Node.js сервер (src/server)
      ├── GET  /            → веб-клієнт (dist/web: html/css/js)
      ├── GET  /api/health  → «живий?» (без токена)
      ├── GET  /api/info    → інформація про модель   (токен)
      └── POST /api/chat    → відповідь моделі стрімом (токен, ліміт запитів)
              │
              ▼
          🧠 модель (src/ai)
```

Сервер **сам віддає і веб-сторінку, і API** на одному порту. Окремий веб-сервер не потрібен.

## Безпека: обов'язковий мінімум

Сервер у відкритому інтернеті сканують боти вже за кілька хвилин після запуску.

1. **ACCESS_TOKEN.** Без нього API відповідає `401`. Токен вводиться один раз у веб-клієнті
   і зберігається в телефоні. Якщо в `.env` порожньо, сервер згенерує токен і надрукує його в лог.
2. **Ліміт запитів** (`RATE_LIMIT_PER_MINUTE`) з однієї IP, щоб ніхто не «спалив» CPU.
3. **Обмеження розміру** запиту й відповіді (вшиті в сервер).
4. **HTTPS.** По голому `http://IP` токен летить відкритим текстом: у кафе на публічному Wi-Fi
   його можна перехопити. Для постійного користування варто взяти безкоштовний домен
   і HTTPS (варіант «Г» нижче) або Tailscale (варіант «В»).

## Вибір варіанта

| Варіант | Складність | Ціна | Коли |
|---------|-----------|------|------|
| **А. Локальна мережа** | ★☆☆ | 0 | телефон у тій самій Wi-Fi, що й ПК. Почніть з цього |
| **Б. Домашній ПК + проброс порту** | ★★☆ | 0 | є «білий» (публічний) IP від провайдера |
| **В. Tailscale** | ★☆☆ | 0 | найбезпечніше: порти не відкриваються, телефон «у мережі» з ПК |
| **Г. VPS + домен + HTTPS** | ★★☆ | ~$4–6/міс | сервер завжди онлайн, статичний IP, ПК може спати |

## А. Локальна мережа (5 хвилин)

```powershell
cp .env.example .env          # заповніть ACCESS_TOKEN
npm install
npm run build:web
npm start
```

Відкрити порт у брандмауері (PowerShell **від адміністратора**):

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\open-firewall.ps1 -Port 3000
```

Скрипт надрукує адреси на кшталт `http://192.168.1.23:3000`. Відкрийте її на телефоні.

## Б. Домашній ПК, доступ з інтернету по IP

1. **Перевірити, чи IP «білий».** Подивіться WAN IP у веб-панелі роутера (зазвичай `192.168.0.1`
   або `192.168.1.1`) і порівняйте з тим, що показує сайт `ifconfig.me` / `2ip.ua`.
   - Збігаються: все ок.
   - Не збігаються, або WAN IP починається з `10.`, `100.64–127.`, `172.16–31.`, `192.168.`:
     це **CGNAT**, проброс не спрацює. Беріть варіант В або Г
     (або замовте у провайдера послугу «статичний/білий IP»).
2. **Закріпити локальну IP ПК** на роутері (DHCP reservation), щоб вона не змінювалась.
3. **Проброс порту** на роутері: розділ *Port Forwarding / Virtual Server / NAT*:
   зовнішній порт `3000` (або будь-який, напр. `8443`) → IP вашого ПК, порт `3000`, TCP.
4. Брандмауер: як у варіанті А.
5. Перевірка: з телефона **через мобільний інтернет** (Wi-Fi вимкнути!) відкрити `http://<білий IP>:3000`.
6. **Динамічний IP?** Якщо провайдер змінює IP, зареєструйте безкоштовний домен
   на [duckdns.org](https://www.duckdns.org) і поставте на ПК їхній оновлювач IP.
7. **Автозапуск** сервера при вході в Windows:
   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy\windows\register-autostart.ps1
   ```

## В. Tailscale (рекомендовано для особистого використання)

Приватна мережа між вашими пристроями. Нічого не відкривається в інтернет, трафік шифрується,
CGNAT не заважає.

1. Встановити Tailscale на ПК (`winget install Tailscale.Tailscale`) і на телефон (App Store / Google Play).
2. Увійти в один акаунт на обох.
3. На телефоні відкрити `http://<tailscale-IP ПК>:3000` (IP вигляду `100.x.y.z`, видно в застосунку).
4. За бажання HTTPS і гарне ім'я: `tailscale serve --bg 3000` дає адресу `https://<ім'я-пк>.<tailnet>.ts.net`.

## Г. VPS + домен + HTTPS

1. Орендувати VPS (Hetzner, DigitalOcean, Vultr тощо): Ubuntu, 1–2 vCPU, 2 ГБ RAM вистачить.
2. Домен: безкоштовний `*.duckdns.org` або свій, з A-записом на IP сервера.
3. На сервері:
   ```bash
   # Docker
   curl -fsSL https://get.docker.com | sh
   # код
   git clone git@github.com:yevhenii-dovhaniuk/ai.git /opt/ai && cd /opt/ai
   cp .env.example .env && nano .env     # ACCESS_TOKEN, DOMAIN, AI_PUBLISH=127.0.0.1:3000
   # брандмауер: лише SSH і веб
   sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw enable
   # запуск з HTTPS
   docker compose --profile https up -d --build
   ```
4. Відкрити `https://<домен>` на телефоні. Сертифікат Caddy отримає сам.

Без Docker: `deploy/linux/ai.service` (systemd) + Caddy, встановлений пакетом.

Оновлення після нових комітів:
```bash
cd /opt/ai && git pull && docker compose --profile https up -d --build
```

## На телефоні: «як застосунок»

Відкрийте сайт → меню браузера → **«Додати на головний екран»**. Веб-клієнт має manifest,
тож відкриватиметься на весь екран, як окремий застосунок.

## Чекліст перед відкриттям в інтернет

- [ ] `ACCESS_TOKEN` довгий і випадковий (≥ 24 символи), `.env` не в git
- [ ] `npm run build:web` виконано (інакше `/` віддасть 404)
- [ ] `curl http://<адреса>/api/health` повертає `{"ok":true,...}`
- [ ] без токена `/api/chat` відповідає `401`
- [ ] за проксі (Caddy/Cloudflare) увімкнено `TRUST_PROXY=true`, інакше ліміт рахується на IP проксі
