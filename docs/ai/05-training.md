# 5. Навчання: як модель стає розумною

Спершу всі ваги випадкові, і модель видає сміття. Навчання — це довгий цикл
«вгадай → подивись на помилку → підкрути ваги».

## Завдання: вгадати наступний токен

Розмітка не потрібна, бо відповідь уже є в самому тексті (**self-supervised**):

```
текст:   [Київ] [ —] [ столиця] [ України]
вхід:    [Київ] [ —] [ столиця]
ціль:    [ —]   [ столиця] [ України]        ← той самий текст, зсунутий на 1
```

Один рядок дає стільки прикладів, скільки в ньому токенів.

## Цикл навчання (training loop)

```ts
for (let step = 0; step < steps; step++) {
  const { inputs, targets } = getBatch(trainData, batchSize, context); // 1. взяти шматки тексту
  const logits = model.forward(inputs);                                // 2. прогноз
  const loss = crossEntropy(logits, targets);                          // 3. помилка
  loss.backward();                                                     // 4. градієнти
  optimizer.step();                                                    // 5. крок по вагах
  optimizer.zeroGrad();
}
```

### Loss: cross-entropy

`loss = -log(p[правильний_токен])`, усереднений по всіх позиціях.
- Випадкова модель зі словником V: `loss ≈ log(V)`. Для 100 символів це ≈ 4.6.
- Добре навчена іграшкова модель на символах: ≈ 1.0–1.5.
- Корисно дивитись на **perplexity** = `exp(loss)`. Це приблизно «зі скількох варіантів
  модель вагається». 4.6 → 100 варіантів (вгадує навмання); 1.2 → ~3 варіанти.

### Backpropagation

Autograd проходить обчислення у зворотному порядку і для кожної ваги рахує,
як вона вплинула на loss (ланцюгове правило похідних). Результат — градієнт `w.grad`.

### Optimizer

- **SGD**: `w -= lr * w.grad`. Найпростіший.
- **AdamW**: пам'ятає ковзне середнє градієнтів і їхнього розкиду, тож кожна вага
  отримує свій розмір кроку. Плюс weight decay (легке «стягування» ваг до нуля).
  Цим вчать майже всі LLM.

## Ключові налаштування

| Параметр | Що це | Типово для іграшки |
|----------|-------|--------------------|
| `learning rate` (lr) | розмір кроку | 1e-3 … 3e-4 |
| `batch size` | скільки шматків тексту за крок | 16–64 |
| `context` | довжина шматка | 64–256 |
| `steps` | скільки кроків | 2 000 – 20 000 |
| warmup + cosine decay | lr спершу росте, потім плавно падає | 100 кроків warmup |

Якщо lr завеликий, loss стрибає або стає `NaN`. Якщо замалий, модель вчиться вічно.

## Train / validation

Частину даних (~10%) **ніколи не показують** моделі під час навчання.
Періодично рахують на них loss:

```
train loss ↓   val loss ↓   → все добре, вчиться
train loss ↓   val loss ↑   → перенавчання (overfitting): модель зазубрює, а не узагальнює
```

Що робити при перенавчанні: більше даних, менша модель, dropout, рання зупинка.

## Чекпоінти

Ваги періодично зберігають у файл (наприклад, JSON або бінарний `Float32Array`).
Так навчання можна продовжити, а сервер просто завантажує готові ваги.
Навчання і використання — **окремі програми**: `npm run train` → файл ваг → `npm start`.

## Чому це працює

Щоб добре вгадувати наступне слово в мільярдах речень, модель змушена всередині
вивчити граматику, факти про світ, логіку й стиль. Ніхто її цього прямо не вчить:
усе це виникає як «побічний ефект» мінімізації однієї цифри, loss.
