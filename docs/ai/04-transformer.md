# 4. Трансформер: збираємо модель

Трансформер — це **стопка однакових блоків**. Кожен блок трохи уточнює вектори токенів.
Перші блоки ловлять прості речі (граматику), глибші — складні (зміст, логіку).

## Один блок

```
 x ──┬──────────────────────┐
     ▼                      │
  LayerNorm                 │
     ▼                      │
  Multi-Head Attention      │   «зібрати інформацію від інших токенів»
     ▼                      │
     + ◄────────────────────┘   residual: x = x + attention(...)
     │
     ├──────────────────────┐
     ▼                      │
  LayerNorm                 │
     ▼                      │
  MLP (feed-forward)        │   «обдумати зібране, кожен токен окремо»
     ▼                      │
     + ◄────────────────────┘   residual: x = x + mlp(...)
     ▼
   вихід блоку (той самий розмір, що й вхід)
```

```ts
function block(x: Vector[]): Vector[] {
  x = add(x, attention(layerNorm(x)));
  x = add(x, mlp(layerNorm(x)));
  return x;
}
```

## Чотири деталі блоку

**1. Attention.** Токени обмінюються інформацією ([03-attention.md](03-attention.md)).

**2. MLP (feed-forward).** Два множення на матрицю з нелінійністю між ними.
Тут, як вважають, зберігається більшість «фактів» моделі.
```ts
const mlp = (x: Vector) => matVec(gelu(matVec(x, W1)), W2); // d → 4d → d
```

**3. Residual (залишкове з'єднання).** Блок не замінює `x`, а **додає** до нього поправку.
Без цього глибокі мережі майже не вчаться: градієнт «загасає» на шляху назад.
З residual у нього є пряма «магістраль» крізь усі шари.

**4. LayerNorm.** Нормалізує вектор (середнє 0, розкид 1), щоб числа не роздувались
і не зникали від шару до шару. Сучасні моделі беруть спрощений **RMSNorm**.

## Уся модель від початку до кінця

```ts
function forward(tokenIds: number[]): number[][] /* logits */ {
  let x = tokenIds.map((id, pos) => add(tokEmb[id], posEmb[pos])); // 2. ембедінги
  for (const b of blocks) x = b(x);                                // 3–4. N блоків
  x = x.map(layerNorm);                                            // фінальна норма
  return x.map((v) => matVec(v, W_out));                           // logits [N × vocab]
}
```

Модель видає logits **для кожної позиції**: «що буде після 1-го токена»,
«…після 2-го» тощо. При навчанні це дає N прикладів з одного рядка тексту.
При генерації використовують тільки останній.

## Розміри (гіперпараметри)

| Параметр | Що це | Іграшка (наша) | GPT-2 small |
|----------|-------|----------------|-------------|
| `vocab_size` | розмір словника | 100–4000 | 50 257 |
| `context` | макс. довжина входу | 64–256 | 1024 |
| `d_model` | довжина вектора | 64–128 | 768 |
| `n_layers` | кількість блоків | 2–4 | 12 |
| `n_heads` | голів уваги | 4 | 12 |
| **параметрів** | всього ваг | ~0.1–1 млн | 124 млн |

Приблизна оцінка параметрів: `12 · n_layers · d_model²` (+ ембедінги).

## Чому саме трансформер

До 2017 року текст обробляли рекурентні мережі (RNN), слово за словом, послідовно.
Трансформер обробляє **всі токени одночасно** (паралельно на GPU), а attention
дає прямий зв'язок між будь-якими двома словами. Через це його можна масштабувати
до трильйонів токенів даних.
