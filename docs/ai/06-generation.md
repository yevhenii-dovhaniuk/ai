# 6. Генерація: як модель пише текст

Модель за один прохід видає ймовірності лише **одного** наступного токена.
Текст з'являється в циклі (**autoregressive**):

```ts
let tokens = tokenizer.encode(prompt);
for (let i = 0; i < maxTokens; i++) {
  const logits = model.forward(tokens.slice(-context)).at(-1)!; // logits останньої позиції
  const next = sample(logits, { temperature, topK, topP });     // вибрати токен
  if (next === EOS) break;                                      // модель сказала "кінець"
  tokens.push(next);
  yield tokenizer.decode([next]);                               // стрімимо клієнту одразу
}
```

Саме тому ChatGPT друкує відповідь по слову: кожне слово — окремий прохід моделі.

## Стратегії вибору токена (sampling)

| Стратегія | Як | Результат |
|-----------|----|-----------|
| **Greedy** | завжди беремо найімовірніший | передбачувано, але часто зациклюється («і і і і») |
| **Temperature** | ділимо logits на T перед softmax | T<1 обережніше, T>1 «креативніше», T→0 = greedy |
| **Top-k** | лишаємо k найкращих, решту викидаємо | відсікає безглузді варіанти |
| **Top-p (nucleus)** | лишаємо найменший набір із сумарною p ≥ 0.9 | адаптивний top-k |
| Repetition penalty | штрафуємо вже використані токени | менше повторів |

```ts
function sample(logits: number[], { temperature = 1, topK = 0 } = {}): number {
  let scaled = logits.map((l) => l / temperature);
  if (topK > 0) {
    const kth = [...scaled].sort((a, b) => b - a)[topK - 1];
    scaled = scaled.map((l) => (l < kth ? -Infinity : l));
  }
  const p = softmax(scaled);
  let r = Math.random();
  for (let i = 0; i < p.length; i++) if ((r -= p[i]) <= 0) return i;
  return p.length - 1;
}
```

## Вікно контексту

Модель бачить не більше `context` токенів. Старші токени просто обрізаються,
і модель їх «забуває». У чаті так зникає початок довгої розмови.

## KV-кеш: прискорення

На кожному кроці attention заново рахує K і V для **всіх** попередніх токенів,
хоча вони не змінились. KV-кеш зберігає їх, і новий крок рахує лише для одного нового токена.
Генерація стає в десятки разів швидшою. Пам'ять за це — головне обмеження серверів LLM.

## Зупинка

Генерація зупиняється, коли:
- модель видала `<|eos|>` (вона вчилась на текстах, що закінчуються цим токеном);
- досягли `maxTokens`;
- зустріли stop-рядок (наприклад, `<|user|>`, тобто модель почала писати за користувача);
- клієнт закрив з'єднання (наш сервер це відстежує).

## Стрімінг до браузера

Сервер віддає токени одразу, як вони з'являються, через **SSE (Server-Sent Events)**:

```
data: {"token":"При"}

data: {"token":"віт"}

event: done
data: {}
```

Так це влаштовано в `src/server/routes/chat.ts` та `web/src/api.ts`.
