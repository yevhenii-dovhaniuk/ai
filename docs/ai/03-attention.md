# 3. Attention: як слова «бачать» одне одного

Після ембедінгів кожен токен — окремий вектор, який нічого не знає про сусідів.
Слово «ключ» може означати і замок, і музику, і джерело води. Значення залежить від інших слів.
**Attention дає кожному токену подивитись на попередні токени й узяти в них потрібну інформацію.**

## Аналогія: пошук у базі

Кожен токен створює з свого вектора три нові (множенням на три матриці ваг):

| Вектор | Роль | Аналогія |
|--------|------|----------|
| **Q** (query) | «Що я шукаю?» | Пошуковий запит |
| **K** (key) | «Що я пропоную?» | Заголовок документа |
| **V** (value) | «Що я віддам, якщо мене оберуть?» | Вміст документа |

Для токена «ключ» у фразі «скрипаль узяв скрипковий ключ»:
- Q(«ключ») приблизно питає: «я про музику чи про двері?»;
- K(«скрипковий») відповідає: «я музичний контекст» → **велика схожість**;
- тому «ключ» забирає багато V від «скрипковий» і стає «музичним ключем».

## Формула (один «головний» рядок усієї LLM)

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
```

Покроково для одного токена:
1. `score_j = dot(q, k_j) / √d` — наскільки кожен попередній токен j релевантний мені.
   Ділення на √d не дає числам стати завеликими.
2. `weights = softmax(scores)` — перетворюємо на частки, що в сумі дають 1.
3. `out = Σ weights_j · v_j` — змішуємо значення попередніх токенів у цих пропорціях.

```ts
function attendOne(q: Vector, keys: Vector[], values: Vector[]): Vector {
  const d = q.length;
  const scores = keys.map((k) => dot(q, k) / Math.sqrt(d));
  const w = softmax(scores);
  const out = new Array(values[0].length).fill(0);
  values.forEach((v, j) => v.forEach((x, i) => (out[i] += w[j] * x)));
  return out;
}
```

## Causal mask: не підглядати в майбутнє

Модель вчиться вгадувати **наступний** токен, тож бачити його заздалегідь не можна.
Токен на позиції `i` дивиться лише на позиції `0..i`. Майбутнім ставлять score `-∞`,
і після softmax їхня вага дорівнює 0.

```
          бачить →  Київ  —  столиця
  Київ              ✔     ✘    ✘
  —                 ✔     ✔    ✘
  столиця           ✔     ✔    ✔
```

## Multi-head: кілька поглядів одночасно

Один attention вміє шукати одне. Тому вектор ділять на `h` частин («голів»),
і кожна голова робить свій attention паралельно: одна стежить за граматикою,
інша за тим, хто що зробив, третя за найближчим словом… Результати склеюють
і пропускають через ще одну матрицю.

```
d_model = 128, heads = 4  →  кожна голова працює з векторами довжини 32
```

## Ціна

Кожен токен порівнюється з кожним, тож вартість росте як **N²** від довжини контексту.
Через це довгий контекст дорогий, і тому існують KV-кеш та різні оптимізації
(див. [06-generation.md](06-generation.md)).
